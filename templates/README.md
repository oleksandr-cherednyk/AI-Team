# Шаблоны — то, что разворачивается под проект

**Ничего из того, что получится из этих шаблонов, не возвращается в репозиторий регламента.**
Заполненные файлы живут в репозитории **проекта** и исключены в [`../.gitignore`](../.gitignore).

| шаблон | во что разворачивается | что там будет |
|---|---|---|
| `PROJECT.md` | `<проект>/PROJECT.md` | единственное проектное место: раскладка, проверки, правила материала, генераторы, линии, стенд, ветки |
| `board/` | `<проект>/board/` | доска: `00-START.md` (есть ли работа), `OPEN.md`, `DONE.md` |
| `memory/_role/` | `<проект>/memory/<роль>/` | по одному каталогу на поднятую роль: `project.md`, `craft.md`, `decisions.md` |
| `ROLE.md` | **`../roles/<ИМЯ>.md`** — исключение: остаётся в регламенте | документ новой роли: восемь разделов с указанием, что писать в каждый, и письмо для ввода сессии |

**`ROLE.md` — единственный шаблон, который разворачивается не в проект, а сюда же, в регламент.**
Роль — это не проектная подробность: заведённая на одном проекте, она годится на следующем. Заводит
её тимлид процедурой **П-7**, и там же — шесть мест, куда роль надо вписать, чтобы её нашли.

**Разворачивает тимлид, процедура П-0** — [`../roles/LEAD-PROCEDURES.md`](../roles/LEAD-PROCEDURES.md).

**Почему шаблон, а не пустой каталог.** Пустой файл читается как «роль не работала»; шаблон говорит,
**какой формы** должна быть запись, и это единственное, что мешает памяти превратиться в свалку.

**Правило заполнения, общее для всех трёх:** запись без случая, из которого она выведена,
недействительна. Пустой раздел лучше выдуманного — он честно говорит «не выяснено».
